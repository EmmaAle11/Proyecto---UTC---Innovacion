01 Las dos propuestas

Una marca, dos caminos de navegación

Ambas comparten el mismo sistema de diseño, marca, componentes y flujo de pago. Difieren en cómo el estudiante descubre y navega el menú. Recomendamos elegir una y profundizarla.

Propuesta A

Mosaico

Login azul institucional y menú en rejilla de 2 columnas con categorías arriba. Navegación plana y directa: ver, agregar, pagar. Ideal si se prioriza catálogo visual y simplicidad.

Propuesta B

Mostrador

Login naranja y feed en columna con tab bar (Inicio · Pedidos · Perfil). Suma un rail “Listos para llevar ya” que impulsa los productos re-ofertados. Ideal para recompra y descubrimiento.

Prototipos navegables: ui_kits/app/index.html (A · Mosaico) y ui_kits/app-mostrador/index.html (B · Mostrador).

04 Ciclo del pedido

Máquina de estados

Pendiente → En preparación → Listo para recoger → Recogido
Ramas: No recogido → re-oferta “Preparados” Cancelado

El admin (panel) avanza el estado a Listo; el usuario recibe notificación push. La ventana de recogida es 10–20 min: si nadie recoge, el pedido pasa a No recogido y sus productos vuelven a ofertarse con la etiqueta “Preparados”.

05 Algoritmo

Tiempos de preparación y re-oferta

Cada producto muestra su tiempo de espera estimado antes de pagar. Ese número es un promedio histórico de las últimas preparaciones reales; si no hay datos suficientes, se usa el tiempo_base del producto.

1 · Estimar el tiempo de espera

// Promedio de las últimas 20 preparaciones reales
function tiempoEstimado(productId):
  muestras = SELECT duracion_min FROM preparation_times
             WHERE product_id = productId
             ORDER BY created_at DESC LIMIT 20
  if muestras.length < 3:
    return producto.tiempo_base        // aún sin histórico fiable
  return round(promedio(muestras))      // minutos

2 · Registrar la preparación al marcar “Listo”

// Acción del admin en el panel
order.estado   = 'listo'
order.ready_at = now()
for item in order.items:
  duracion = minutos(order.ready_at − order.accepted_at)
  INSERT preparation_times(item.product_id, duracion, now())
notificarPush(order.user_id, "Tu pedido está listo, pásale a recogerlo")

3 · Ventana de recogida y re-oferta

// Job programado cada minuto
for order in pedidosEnEstado('listo'):
  esperaListo = minutos(now() − order.ready_at)
  if esperaListo > 20:                     // venció la ventana 10–20 min
    order.estado = 'no_recogido'
    for item in order.items:
      reofertar(item.product_id, tag = 'Preparados')

En la UI, “Listo hace N min” = now() − ready_at. Mantiene mínimos y máximos de stock con la etiqueta “Preparados” para no desperdiciar producto.

06 Pagos

Métodos y resiliencia

El checkout ofrece cinco métodos. Los pagos en línea pasan por un circuit breaker: ante fallas de la pasarela, se corta temporalmente el intento y se sugiere otro método.

Mercado PagoPayPalTarjeta de crédito (TDC)Tarjeta de débito (TDD)Efectivo al recoger

“Efectivo al recoger” no requiere pasarela: el pedido entra a cocina y el cobro se hace en el mostrador.
